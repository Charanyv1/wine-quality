# Wine Quality Prediction Using Deep Learning

Predicts whether a red wine is of good quality (sensory score ≥ 7) from its 11 physicochemical
properties, using a deep neural network built with TensorFlow/Keras and served through a Streamlit app.

## Project Structure

- `train_model.py` — builds, trains and evaluates the Keras DNN; writes every artifact.
- `app.py` — Streamlit app that loads the trained model and predicts on user input.
- `winequality-red.csv` — UCI red wine dataset (1599 rows, 11 features + quality score).
- `model.ipynb` — original exploratory notebook (kept for reference).
- `artifacts/` — generated by training:
  - `wine_quality_dnn.keras` — trained model
  - `scaler.pkl` — `StandardScaler` fitted on the training split only
  - `metrics.json` — architecture details and measured test metrics
  - `accuracy_plot.png`, `loss_plot.png`, `confusion_matrix.png`

## How to Run

```sh
pip install -r requirements.txt   # install
python train_model.py             # train (writes artifacts/)
streamlit run app.py              # run the UI
```

Training takes well under a minute on CPU. The app refuses to start until the artifacts exist.

## Deep Learning Concepts in the Code

**Activation functions** — ReLU (`max(0, x)`) in the hidden layers: its derivative is 1 for positive
inputs, so gradients do not vanish through the stack the way they do with sigmoid/tanh, and it is cheap
to compute. The output uses sigmoid to squash the final logit into (0, 1) so it reads as a probability.

**Loss function** — binary cross-entropy, `-[y·log(p) + (1−y)·log(1−p)]`, the negative log-likelihood of
a Bernoulli target. It punishes confident wrong answers steeply and, combined with a sigmoid output,
gives the clean gradient `p − y`.

**Optimizer** — Adam at learning rate 0.001. Adam keeps exponentially decaying averages of the gradient
(first moment `m`) and of the squared gradient (second moment `v`) per parameter and steps
`w ← w − lr · m̂ / (√v̂ + ε)`, so each weight gets its own adaptive step size plus momentum.

**Forward propagation and backpropagation** — `model.fit` pushes each batch forward through the layers
to produce predictions and a loss, TensorFlow records those operations on a `GradientTape`, then
backpropagation replays the tape in reverse using the chain rule to compute `∂Loss/∂w` for every
parameter, and Adam applies the update. This repeats for every batch of every epoch.

**Training configuration** — up to 100 epochs, batch size 32, `EarlyStopping(monitor='val_loss',
patience=15, restore_best_weights=True)`, a stratified 64/16/20 train/validation/test split
(1023/256/320 rows), and a `StandardScaler` **fitted on the training split only** and then applied to
validation and test, so no held-out statistics leak into training.

**Class imbalance** — only 13.6% of the wines are good quality, so `class_weight` scales the minority
class loss up. Without it the network reaches a higher raw accuracy by rarely predicting "good", which
is useless for the actual task.

## Evaluation Results

Measured on the held-out 320-row test split from the run that produced `artifacts/` (seed 42,
early stopping triggered after 25 of 100 epochs):

| Metric | Value |
|---|---|
| Accuracy | 0.838 |
| Precision (good) | 0.438 |
| Recall (good) | 0.744 |
| F1-score (good) | 0.552 |
| ROC AUC | 0.877 |

```
              precision    recall  f1-score   support

    not good       0.96      0.85      0.90       277
        good       0.44      0.74      0.55        43

    accuracy                           0.84       320
   macro avg       0.70      0.80      0.73       320
weighted avg       0.89      0.84      0.85       320
```

Confusion matrix (rows actual, columns predicted): `[[236, 41], [11, 32]]`.

Class weighting deliberately trades precision for recall: the model catches 74% of the good wines at the
cost of flagging some average ones. ROC AUC of 0.877 shows the ranking quality is solid regardless of
where the 0.5 threshold sits. Re-running `train_model.py` reproduces these numbers with the fixed seed;
the app always displays the metrics from `artifacts/metrics.json`, never hardcoded values.

## Streamlit App

- All 11 properties as labelled `st.number_input()` fields in a two-column layout, with units and
  typical ranges in the help text.
- **Predict Wine Quality** button, input validation, and a result panel showing the predicted class,
  model confidence and `P(good quality)`.
- The model, scaler and metrics load once via `@st.cache_resource` — no retraining on rerun.
- An **About the Deep Learning Model** expander with the architecture, hidden-layer count, activations,
  loss, optimizer and learning rate, epochs completed, measured test metrics, the classification report,
  and the training/validation loss and accuracy curves plus the confusion matrix.
